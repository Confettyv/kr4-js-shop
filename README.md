Контрольная работа №4 по дисциплине «Фронтенд и бэкенд разработка».

**Тема:** «JavaScript: интерактивность, DOM, события, формы и валидация».

**Опубликованный сайт:** https://confettyv.github.io/kr4-js-shop/

## Описание

Интерактивная версия адаптивного магазина «Рекорд» из КР №3 на чистом JavaScript, без библиотек. Каталог, страница товара и корзина строятся скриптами из массива товаров, формы проверяются на стороне браузера, корзина сохраняется в `localStorage`.

## Реализовано

**Обязательная часть**

- массив из 12 товаров с единой структурой: `id`, `title`, `category`, `price`, `isAvailable` и дополнительные поля;
- карточки товаров на главной, в каталоге и в блоке «С этим товаром покупают» генерируются из массива;
- поиск по названию без учёта регистра;
- фильтр по категории;
- сортировка по цене (по возрастанию и убыванию), названию и рейтингу;
- валидация формы заявки, обратной связи и формы консультации в модальном окне;
- ошибки и сообщения об успехе выводятся на страницу, `alert()` не используется;
- DOM строится через `createElement`, `textContent`, `classList`, `append`, `replaceChildren`;
- все обработчики подключены через `addEventListener`;
- пользовательские данные нигде не вставляются через `innerHTML`.

**Самостоятельные доработки**

- **Корзина** на отдельной странице `cart.html`: добавление из карточек и со страницы товара, изменение количества кнопками «−/+», удаление, очистка.
- **Сумма корзины через `reduce`** и **промокоды**: `REKORD10` — скидка 10%, `SPORT500` — 500 ₽ при заказе от 5 000 ₽; для второго проверяется минимальная сумма.
- **localStorage**: корзина и применённый промокод переживают перезагрузку; последняя заявка сохраняется. Счётчик в шапке синхронизируется на всех страницах.
- **Страница товара по параметру адреса** `product.html?id=5`: заголовок вкладки, хлебные крошки и похожие товары подставляются из данных; неизвестный `id` показывает «Товар не найден», товар не в наличии — без кнопки покупки.
- **Фильтр «Только в наличии»** и **кнопка «Сбросить фильтры»**.
- **Пагинация**: по 6 товаров на странице.
- **Пустые состояния** каталога и корзины.
- **Переход по категориям**: ссылки `catalog.html#run` с главной сразу открывают нужную категорию.
- **Имитация отправки**: кнопка блокируется, показывается «Отправляем…», затем сообщение с номером заявки; корзина очищается.
- **Расширенная валидация**: адрес обязателен только при доставке курьером; ошибка исчезает, как только поле исправлено; фокус переходит на первое неверное поле; `aria-invalid` и `aria-describedby` для экранных дикторов.
- **Всплывающее уведомление** «Товар в корзине».

## Структура проекта

```text
kr4-js-shop/
├── index.html, catalog.html, product.html, cart.html,
│   order.html, contacts.html, delivery.html
├── css/
│   ├── style.css        — стили (Mobile First) + блоки корзины, ошибок, уведомлений
│   └── responsive.css   — медиазапросы
├── js/
│   ├── data.js          — массив товаров, категории, промокоды
│   ├── storage.js       — чтение и запись localStorage с защитой от ошибок
│   ├── utils.js         — форматирование цены, склонение, безопасное создание элементов
│   ├── cart.js          — логика корзины, промокоды, страница корзины, счётчик в шапке
│   ├── catalog.js       — карточки, поиск, фильтры, сортировка, пагинация
│   ├── product.js       — страница товара по параметру id
│   ├── modal.js         — модальное окно, уведомления, мобильное меню
│   ├── validation.js    — правила проверки и обработчики форм
│   └── main.js          — инициализация: запускает нужные модули на каждой странице
├── images/
├── README.md
└── .gitignore
```

Скрипты подключены с `defer` в порядке зависимостей: данные → хранилище → утилиты → корзина → каталог → товар → модальное окно → валидация → `main.js`. Все файлы только объявляют функции, а запускает их `main.js`, поэтому порядок важен лишь для него.

## localStorage

| Ключ | Что хранится |
|---|---|
| `rekord-cart` | массив `[{ id, quantity }]` — товары в корзине |
| `rekord-promo` | код применённого промокода |
| `rekord-last-order` | номер и параметры последней отправленной заявки |

При чтении данные проверяются: неизвестные товары и неверные количества отбрасываются, поэтому испорченная запись не ломает страницу. Если `localStorage` недоступен (приватный режим), сайт работает без сохранения.

## Как проверить

1. Главная → «В корзину» у любого товара: счётчик в шапке увеличится.
2. Каталог: введите «мяч», выберите категорию «Силовые», отсортируйте по цене, включите «Только в наличии»; введите «ааа» — появится пустое состояние.
3. `product.html?id=5` — страница гири; `product.html?id=999` — «Товар не найден».
4. Корзина: измените количество, примените `REKORD10`, перезагрузите страницу — всё сохранится.
5. Заявка: отправьте пустую форму — появятся ошибки под полями; заполните и отправьте — появится номер заявки.

Все сценарии выше проверены автоматическим прогоном в Chrome: 45 проверок, ошибок в консоли нет.

## Отладка

В `catalog.js` при каждой перерисовке каталога в консоль выводится состояние фильтров и число найденных товаров (`console.debug`), а `main.js` сообщает о запуске скриптов. Для пошаговой отладки удобно поставить точку останова в функции `getVisibleProducts` и изменить фильтр.

## Запуск

Сборка не нужна. Из-за `localStorage` и параметров адреса лучше открывать через локальный сервер:

```bash
python3 -m http.server 8000
```
